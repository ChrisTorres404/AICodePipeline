# 1.4.2

A hardening release: fifty-one fixes found by reviewing 1.4.1 line by line. Closing a work
order now holds more strictly to evidence that matches the code, the drivers refuse bad input
instead of writing broken or half-made documents, and titles, paths and settings are treated
as plain text everywhere. There are a few small additions, such as `acp test` checking that
every evaluation ran, and the evaluation suite grew from 58 to 109.

After upgrading, run `wo verify` again on each open order: the upgrade changes installed files
inside the fingerprinted tree, so a PASS recorded before it reads as stale. In a project kept
under a home folder, `acp test` still reports one sanitize finding in a shipped evaluation, as
1.4.1 did; that is fixed in the next release.
