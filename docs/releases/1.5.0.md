# 1.5.0

A layout release. A project can now keep its code and the pipeline apart, with the product in
app/ and the pipeline and its work in acp/. New projects can start that way, and `acp migrate`
moves an existing one in four steps: a plan that moves nothing, a checked backup, your answers
to the plan's questions, and one commit that makes the move. acp doctor and acp check now name
what sits outside the layout, hold every work-order and bug folder to one structure, and warn
when a project's .gitignore lets secret files into git. Every order gets an artifacts/ folder for
working files that never enter git, the commit hook refuses the keys sanitize finds, and the
evaluation suite grew from 109 to 131.

After upgrading, run `acp doctor`. An older project will see warnings for stray files in its
order folders, which `acp migrate plan` files for you, and for .gitignore lines to add, which
`acp doctor --gitignore-hint` prints; doctor never edits the file itself. As with 1.4.2, run
`wo verify` again on each open order.
