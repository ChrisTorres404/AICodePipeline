# migrate-apply

Proves: acp migrate apply restructures a project made by new-project into acp/ (the pipeline, its playbooks and workspace) and app/ (the product) as one commit made without hooks, leaving what tools read at the root there, keeping every tracked file (one ignored at its new place included) at its new place with the same content, moving a root handoff after the workspace, repairing a moved order worktree and mapping open orders' manifests, declared paths and worktree records (the originals kept), and carrying ignored files with their folders; that it refuses with one line, changing nothing, before anything moves: an unanswered or edited answer, pinned, stop the migration, another plan, an installed copy or another version of ACP running it, a backup that does not match, uncommitted or untracked files, app/ already there, a destination already taken, a link the moves would break, a config acp layout refuses, a filter a tracked file uses (a global one no file uses does not refuse), no git identity, an earlier apply (with the way back), an unpushed commit, a held lock, a malformed order manifest; that a failure or an interruption before the install, at the first step, at the layout step, or a file a moved .gitignore pattern would no longer ignore, puts every step back so the backup checks whole and apply can run again; and that from the install on, a failure or an interruption stops with a record of where and the way back (the printed tar command, which restores the project as backed up), never committing a stray file, a new gitlink, a deletion it did not plan, or the plan folder.
