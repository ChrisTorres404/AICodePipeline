# migrate-plan-apply-accepts

Proves: `acp migrate plan` never offers or suggests an answer apply would refuse (a loose document whose place is a person's work, "by hand", or no folder, "dropped", is offered keep or delete, keep suggested; one apply files into acp/ is offered yes), and records any suggestion apply would refuse so it is shown; it predicts the ignored files the moves would make visible (each .gitignore copied to where the moves leave it, in a scratch repository, and git check-ignore asked about each file at its new place) and asks one question offering the anchored lines that keep them ignored, yes suggested; apply adds them, journalled, when the answer is yes, and its own check after the moves still catches them when it is no, putting every move back. Patterns that still match at the new place ask nothing. The plan and apply read one set of move rules, `planned_moves`, which gives exactly what preflight's own block gave on be1bfab (recorded per case).
