# order-structure

Proves: every work-order and bug folder follows one structure: only order folders (`WO-NNNN-words`, `BUG-NNNN-words`) under the work-order and bug folders, each holding only its driver files, documents named for its own number, the drivers' verification logs and one artifacts/ folder, which wo new, wo start, wo adopt, bug new and bug adopt make. The work-order and bug folders' own .gitignore (`/*/artifacts/`, kept by install, new-project, wo new, bug new and both adopts; a block beside the file's own lines, CRLF kept, a link or an unpaired marker refused) keeps every order's artifacts/ out of git in the checkout, an order's worktree and a fresh clone; a file git sees there anyway is a failure under every profile, at doctor and at commit, and says to restore the rule with acp install. A loose file, a bad folder name, another order's document, an unknown file or a subfolder is a stray: a warning, and a failure under the strict profile, with a message that says where it goes; editor and system files are never one, and more than a handful point at acp migrate. A suite named for an order whose folder is gone fails under any profile; the suites folder is otherwise the project's own, and a TESTING_DIR written with a variable leaves only the suites unjudged. Warnings: a README beside the orders, documents an order's size requires but lacks (bin/wo's own table), a CLOSEOUT beside status=open or status=closed without one. wo close and bug close write status=closed; a title with no letter a folder name can hold makes an `untitled` folder; adopt in place files the record it is given under the order's document name (git mv when tracked; a taken name refused) and says what else it keeps. Promote leaves artifacts/ out of the playbook at any depth and says so when it held files, sanitizes exactly what it copies and names a finding in the order, refuses an artifacts/ that is a link, and leaves no stage behind.
