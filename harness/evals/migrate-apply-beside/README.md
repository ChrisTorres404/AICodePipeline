# migrate-apply-beside

Proves: acp migrate apply, after its move commit, carries out what lies beside the repository as the owner answered: an order only outside is imported (its manifest and declared paths mapped, the old manifest kept in the migration record) or retired (kept whole in the record as copy-of-<order>, committed, listed, never an order, its artifacts/ moved to the private folder and not committed); placeholder orders are adopted under new numbers with their files renamed, and a placeholder note through the installed wo adopt; an order in two places that differ is merged (the only-outside files carried in, the answered side's version landing, the other kept under kept/, or in the private folder when it holds a key line); each order's stray notes and artifacts are filed (an artifact ignored through the orders folder's .gitignore); private material moves to the private folder and is named in the record only as a numbered item; logs and residue go to a logs folder git ignores; a knowledge-base snapshot is dropped only when every file is reachable in the repository's history; a second ACP copy with nothing unique is removed; a root document answered delete is deleted in the second commit; the merged branch answered delete is deleted; and the migration record is committed in a second commit, run with the project's hooks, naming no path of this machine in any form (the private folder answered through a link, with a trailing slash), the migrated project passing the structure rule. It refuses with one line, changing nothing, before anything moves: file by file, a commit that would carry a secret, adopting a file that is not a note, a source holding a link out of it, a destination already taken or below a link, a branch a worktree has checked out (suggested keep by the plan), a branch or an item changed since the plan, a plan made before apply could check digests. After the move commit it stops at the first surprise, with what is committed and the way back, leaving every tracked file as the move commit left it and nothing of the step in hand: an item changed before its deletion, a refused second commit (nothing beside the repository deleted), a branch moved since the plan (not deleted), and failures planted in process (ACP_TEST_FAIL): a failed copy, an interrupt, a merge failing at its second replacement (the repository's versions put back first) or its second saved copy, a destination taken during apply, and a path of this machine left in the record.
