# check-staged-content

Proves: acp check --staged, run from the top or a subfolder, judges what the commit holds (the index, read in one listing however many files are staged), not the working copy, including a staged file gone from disk, and blocks an entry git cannot read back; every staged text file is read whatever its kind, with one rule shared by acp check and the commit hook: every text file with the whole key list (code, configuration, infrastructure, .vue, .envrc, .ps1, Jenkinsfile and the rest) and its placeholders passing, except prose and data (.md, .txt, .rst, .adoc, .csv, .log, .html), which take sanitize's vendor-shaped keys only; removing a binary file is not refused; binary files and links are left alone, while text git calls binary by attribute, and UTF-16 text, is read; a commit inside quoted text is a commit however the text is run (bash -l -c, su -c, python3 -c and the rest), while a folder in quoted text counts only for sh -c and eval; the folder a command finds for itself ($(pwd), $PWD, its repository's top) is judged; and a payload of any shape is answered, while a hook that breaks refuses a commit.
