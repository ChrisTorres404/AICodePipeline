# secret-ignores

Proves: a new project's .gitignore, in the default layout and in acp/ + app/, ignores `.env` and `.env.*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa*`, `id_ed25519*` and `id_ecdsa*` (and `.venv/`, `venv/`, `coverage/`, `.pytest_cache/`, `*.tmp`), keeps `.env.example`, `.env.sample`, `.env.template` and every `.pub` key in git, and keeps the template's earlier lines in their order. acp doctor tests a project's own .gitignore files by name with git check-ignore (at the root and in the code folder; never .git/info/exclude or a global excludes file, which a clone does not carry): it passes a new project, warns of an older one naming what gets in and printing the lines to add, and never writes the file; `acp doctor --gitignore-hint` prints exactly those lines (a negation after the lines it answers), and with them added the warning is gone. The pipeline's own repository ignores its top-level `Private-*` folders by one generic rule.
